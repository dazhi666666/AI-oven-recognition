# C-01 方法与接口

## 1. 接口契约

### 1.1 预测入口

```python
from stereo import estimate_depth

result = estimate_depth(
    left_path,                 # 左图路径（灰度或彩色，内部转 8 位灰度）
    right_path,                # 右图路径，必须与左图同尺寸
    config=C01_DEFAULT,        # 固定配置对象（含 config_id）
    calibration=None,          # None => 只出视差；给定 => 另出米制深度
    input_id=None,             # 仅用于元数据命名，不参与计算
    provenance=PROVENANCE_ARTIFICIAL,  # 输入来源声明，必填语义
    depth_range_m=None,        # 可选 (z_min, z_max)，只用于覆盖检查报告
)
```

**签名里没有任何真值/参考参数**，这是结构性隔离，不是承诺：`tests/stereo/test_isolation.py`
解析 `src/stereo/pipeline.py` 的 AST，检查它既没有导入 `stereo.reference`，也没有调用
OpenCV 匹配 API，字符串常量里也不出现真值文件名。

### 1.2 输出

`result: StereoRunResult`，核心字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `disparity_px` | `float32 HxW` | 左图列系视差，**单位像素**；**无效位置是 `NaN`** |
| `disparity_valid_mask` | `bool HxW` | 显式有效掩膜，与 `NaN` 位置严格互补 |
| `disparity_raw` | `int16 HxW` | OpenCV 原始输出（定点，未解码），保留以便复核 |
| `depth_m` | `float32 HxW` 或 `None` | 轴向米制深度；无标定时为 `None` |
| `depth_valid_mask` | `bool HxW` 或 `None` | 深度有效掩膜 |
| `mode` | `str` | `"disparity_only"` / `"disparity_and_depth"` |
| `config` | `SGBMConfig` | 实际使用的配置（含 `config_id`） |
| `calibration` | `StereoCalibration` 或 `None` | 实际使用的标定 |

约定（不是建议，是接口语义）：

1. **无效像素必须显式保留**：`NaN` + `False` 掩膜，不填 0、不插值、不填充。下游若把 `NaN`
   当数值用会看到 `NaN` 传播，而不是被悄悄替换成"看起来正常"的深度。
2. **不给出达标结论**：本包不做误差达标判定；误差统计交给 D 的独立工具。
3. `save(dir)` 落盘文件名固定：`disparity_px.npy`、`disparity_valid_mask.npy/.png`、
   `depth_m.npy`、`depth_valid_mask.npy/.png`、`disparity_raw.npy`、`disparity_vis.png`、
   `depth_vis.png`、`run_metadata.json`、`config.json`、`calibration.json`、`PROVENANCE.txt`。

### 1.3 错误码（拒绝而不是猜）

| 错误码 | 触发 | 为什么必须拒绝 |
|---|---|---|
| `E_SIZE_MISMATCH` | 左右图尺寸不一致 | 未校正/裁切不一致时列对应关系不成立 |
| `E_READ_FAIL` | 图像不存在/不可读 | 静默回退会产出无意义数值 |
| `E_UNSUPPORTED_DEPTH` / `E_UNSUPPORTED_CHANNELS` | 非 8/16 位或异常通道 | 单位与解码都不可确定 |
| `E_INVALID_SEARCH_PARAMS` | `numDisparities` 非 16 倍数、`blockSize` 非奇数等 | **OpenCV 不校验**（见实测记录），必须由本层拦住 |
| `E_NOT_RECTIFIED` | 标定 `is_rectified=False` | 未校正图像不能直接做水平匹配 |
| `E_CALIB_SIZE_MISMATCH` | 标定分辨率 ≠ 图像尺寸 | 内参与主点差不可跨分辨率移植 |
| `E_INVALID_CALIBRATION` | `fx<=0` / 基线非正等 | 换算会产出负深度或除零 |
| `E_NO_DEPTH` | 无标定却要求深度 | 拒绝用默认参数编造米制值 |
| `E_BAD_PROVENANCE` | 来源声明非法 | 防止人工构造输入被当成真实链路 |
| `E_BAD_DEPTH_RANGE` | `depth_range_m` 非法 | 覆盖检查输入需可信 |
| `E_UNSUPPORTED_RAW_DTYPE` | 未知 OpenCV 输出 dtype | 缩放因子不确定时拒绝猜测 |

`outputs/stereo-c01/error_cases.json` 里 8 个最小用例全部按预期拒绝（`error_cases_all_passed: true`）。

## 2. 方法

链路只有四步，每步都可单独测试：

1. **读图与校验**：`read_gray_pair` → 尺寸/通道/位深校验 + 每文件 sha256（元数据可追溯）。
2. **SGBM 求视差**：`build_matcher` → `compute`。**用 OpenCV 现成实现**，未自写 SGM，
   因为 C-01 的目标是拿到可信数值，不是复现算法。
3. **单位解码**：`decode_disparity` → `disparity_px = raw / scale`，`scale` 由
   dtype 先验（整型=16.0，浮点=1.0）给出，并**实测核验**（见下）。
4. **深度换算**：`depth_from_disparity` → `Z = fx * B / (d - doff)`，`doff = cx_left - cx_right`。
   `d - doff <= 1e-3` 的像素判为无效（`MIN_USABLE_DISPARITY_ABOVE_DOFF_PX`），不给 `inf`。

### 2.1 单位为什么需要"实测核验"

OpenCV 的 SGBM **返回 `int16` 定点值（视差 ×16）**，且无效像素编码为 `(minDisparity-1)*16`。
这两点若猜错，深度会整体差 16 倍且毫无报错。所以本包不靠"文档记忆"：

- `verify_disparity_units(config)` 在人工构造的斜平面图上同时按 `scale=16` 与 `scale=1`
  解码，比较与解析真值的中位绝对误差，只有正确缩放胜出且误差足够小才通过，否则抛
  `StereoUnitError`（阈值 `UNIT_CHECK_MEDIAN_ABS_ERR_MAX_PX = 0.5`，并要求明显优于错误假设）。
- 实测结果（本机 OpenCV 5.0.0）：`scale=16` 中位绝对误差 **0.1000 px**（49920 像素），
  `scale=1` 为 **493.4 px** —— 判别是决定性的，不是擦边通过。
- 核验结果按 `(config_id, cv2.__version__)` 缓存；`force=True` 可强制重算。
- 该核验只使用**人工构造图样**，不接触任何真实数据，也不产生"精度达标"含义。

### 2.2 人工构造图样（`stereo.testpatterns`）

- `render_slanted_plane_pair`：解析线性视差，右图由纹理按 `x_l = (x_r + d0)/(1 - k)` 重采样，
  真值 `d_gt(x_l) = d0 + k·x_l`，并返回 `valid_gt`（右图采样落在纹理内的列）。
  当前默认 `d0=16`、`k=0.10`、`seed=3`、`240x320`，真值视差区间 `[16.0, 47.9]`。
- **常数视差平面不可用作解码核验**：它在 SGBM 下属病态输入（同一纹理整行平移，SGBM 的
  代价聚合缺少可区分的匹配峰），实测中位误差可达数十像素。这不是本包缺陷，而是该输入的
  性质；`render_constant_shift_pair` 仅用于"能否跑通"的冒烟测试，不用于单位核验。
- 每个图样都带 `meta.provenance = "artificial_test_pattern"` 与中文说明；产物里另有
  `PROVENANCE.txt`，`is_real_scene_chain()` 恒为 `False`。

## 3. 参数选择依据

固定配置 `C01_DEFAULT`：`minDisparity=0`、`numDisparities=64`、`blockSize=5`、`P1=200`、
`P2=800`、`disp12MaxDiff=1`、`uniquenessRatio=10`、`speckleWindowSize=100`、`speckleRange=2`、
`preFilterCap=63`、`mode=SGBM`。另备 `C01_OVEN_RANGE`（`numDisparities=256`，
标签 `verified=False`）。

选择依据是**几何**，不是调参：

1. **深度区间反算视差区间**：`d = doff + fx·B/z`。近视差大、远视差小，所以
   `required_disparity_range(fx, B, z_max, z_min, doff)` 给出 `[d_min, d_max]`。
2. **覆盖检查**：`check_search_range_covers(...)` 对比配置的 `[minDisparity, minDisparity+numDisparities)`
   与所需区间，报告 `covers_nearest` / `covers_farthest` / `covered`，以及未覆盖时**会坏在哪一侧**。
   它只报告，不改配置。
3. **左边界代价**（本轮实测新发现，写进 `left_border_invalid_columns`）：
   **左起 `numDisparities` 列恒为无效**，与图像宽度无关（8 组 宽度×`numDisparities` 组合全部一致）。
   所以 `numDisparities` 不只是搜索范围，还是一笔固定的像素代价：320 宽的图上用 256，
   理论上限就只剩 20% 有效列。选参数必须同时看深度覆盖与图像宽度。
4. 该结论被测试钉住：`tests/stereo/test_sgbm_wrapper.py::test_valid_region_matches_coverage_prediction`
   断言"覆盖检查说够用 ⇒ 左边界之外确实几乎全有效；说不够用 ⇒ 确实整片失效"，
   在 320/640 宽 × 32/64/128/256 上全部成立。

> 本轮**没有**任何"这套参数在真实数据上够用"的证据：真实视差范围未知，`numDisparities`
> 的真实取值必须等 B 的真实标定与 D 的口径。

## 4. 复跑

所有命令都在本文件夹 `AI_oven_recognition/` 下执行。

环境：本文件夹内的 `.venv/`（Python 3.13.13 + numpy 2.5.4 + OpenCV 5.0.0 + pytest 9.1.1），
依赖固定在 `requirements.txt`。该 venv **不入库**，按下面命令随时重建。

如需从头重建环境（本机网络到 `pypi.org` 不通，用清华镜像）：

```bash
cd AI_oven_recognition
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt \
  -i https://pypi.tuna.tsinghua.edu.cn/simple/
```

测试（102 项）：

```bash
cd AI_oven_recognition
PYTHONPATH=src .venv/bin/python -m pytest tests/stereo -q
```

产物（重新生成 `outputs/stereo-c01/`）：

```bash
cd AI_oven_recognition
PYTHONPATH=src .venv/bin/python -m stereo.run_c01 --out outputs/stereo-c01
```

> `tests/stereo/pytest.ini` 注册了 `unit` / `integration` / `slow` 标记。刻意**没有**在本文件夹
> 顶层放 `pytest.ini`，避免在仓库根产生全局副作用（影响其他子项目的测试收集）。

## 6. 未完成与待确认（不得当成已完成）

1. **真实数据未跑通**：无 B 的真实已校正左右图与真实 `P1/P2`，`doff` 目前是人工假设值。
2. **精度未评估**：无任何达标声明；误差统计需 D 的工具在留出数据上做。
3. **参数未定**：`C01_DEFAULT` 的 `numDisparities=64` 是几何推导 + 人工图样下的选择，
   真实视差范围未知；`C01_OVEN_RANGE` 标 `verified=False`。
4. **标定来源单一**：仅支持 `P1/P2`（推荐）与 `fx/B/doff` 两种构造；未处理
   `cv2.stereoRectify` 之外的畸变残差、未处理左右图曝光/增益差异（真实数据上可能影响匹配）。
5. **纹理弱/重复纹理**未评估（人工图样是有纹理的合成图，不能代表真实弱纹理场景）。
6. **`cv2.StereoSGBM` 类构造器段错误**只是被规避（走 `*_create`），根因未定位到 OpenCV 侧 issue；
   换版本时 `tests/stereo/test_sgbm_wrapper.py` 的断言会提醒重新确认。
7. 入口图为**静态图对**；视频/连续帧一致性、时域平滑不在 C-01 范围内。
