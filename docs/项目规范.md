# 项目规范

写代码、提交之前先看这一页。目的只有一个：四个人（和各自的 AI）写出来的东西能直接拼在一起用，不用事后返工。

---

## 1. 东西放哪

| 内容 | 放在 | 进 Git |
|---|---|---|
| Python 代码 | `src/oven_stereo/<模块>/`（data、synthetic、calibration、stereo、geometry、evaluation、pipeline） | 进 |
| 模块之间交换的数据格式 | `src/oven_stereo/contracts/` | 进 |
| 测试 | `tests/<模块>/` | 进 |
| 参数 | `configs/<模块>/*.yaml` | 进 |
| 文档 | `docs/<模块>/`；需要拍板的决定放 `docs/decisions/` | 进 |
| 板端 C 代码 | `edge/` | 进 |
| 原始数据、中间数据 | `data/raw/`、`data/interim/` | **不进** |
| 运行结果（npy、png、日志） | `results/<任务编号>/<每次运行一个文件夹>/` | **不进** |

**不要做的事：**

- **新建顶层目录。** 尤其不要做"自包含交付包"，也就是在仓库里另起一个带自己 `README`、`requirements`、`src/`、`tests/` 的文件夹。所有代码都放进上面的统一结构。
- **在 `src/` 外面再建 Python 包**，或者另起一个和 `oven_stereo` 平级的包名。
- **提交运行结果、虚拟环境、缓存、对话记录导出，或个人工具的本机状态文件。**

---

## 2. 环境和依赖

- **统一环境：** 所有人都用 `requirements-lock.txt` 里的版本，装在仓库下的 `.venv` 里。步骤见 readme 的"环境安装"。
- **不要另写一份 requirements，也不要改用别的版本。** 例如自己换成 OpenCV 5.0 或 Python 3.13：OpenCV 不同版本的行为可能不一样，在别的版本上测出来的结论不能直接用。
- **确实要加依赖时：**
  1. 先在 `.venv` 里装好，跑通全部测试；
  2. 同时改 `pyproject.toml` 和 `requirements-lock.txt`；
  3. 在任务记录里说一句为什么加。

---

## 3. 模块之间怎么接

- **数据交换用统一格式。** 模块之间只用 `contracts` 里定义的格式交换数据，不要各自发明一套字段名。目前已有的格式：
  - `RectifiedStereo`：已校正双目的标定参数；
  - `DepthResult`：深度结果。
  - `GeometryResult`：A-02 已知支撑平面高度网格的测量结果（不等于完整深度转几何流程）。

  需要新格式就加到 `contracts/` 里，并在任务记录里提一句。
- **复用别人的代码，不复制。** 要用别人模块的功能，就 import 过来。发现有问题，直接改原处，并告诉作者。
- **打分程序独立。** `evaluation/` 不 import `stereo/`、`geometry/` 的算法代码。
- **大家共用的约定**（详见[共同约定与接口](ai/00_共同约定与接口.md)第 5 节）：

| 约定 | 内容 |
|---|---|
| 单位 | 长度一律用米，视差用像素 |
| 视差 | `d = 左图横坐标 − 右图横坐标` |
| 主点差 | `doffs = 右相机主点 x − 左相机主点 x`，距离 `Z = f·B / (d + doffs)` |
| 坐标系 | 以左摄像头为原点，x 向右、y 向下、z 向前 |
| 无效点 | 数组里填 NaN，另附一张 bool 掩膜；**不要填 0** |

## 4. 代码怎么写

- **算法函数接收数组，不接收文件路径。** 读写文件放在 `data/`（读）或结果的 `save()`（写）里。这样算法才能直接拿来测试、拿来组合。
- **参数写进 YAML**，不写死在代码里，也不要在代码里放"预置参数组"。
- **不用没核实过的假设参数。** 相机参数、距离范围等，一律按项目设定（见[系统架构](architecture.md)第 4 节）或实测值；如果只是临时假设，要在注释里写明。
- **简单优先：**
  - 不为每次运行额外加自检流程。该固定的行为，用单元测试固定下来；
  - 不写只检查源码文字或文档措辞的测试；
  - 出错时直接抛标准异常（`ValueError`、`FileNotFoundError` 等），信息里写清楚哪里错了，不需要自定义一堆错误码。
- **风格：** 中文注释、简短；跟周围已有代码的写法保持一致。

---

## 5. 测试

- **提交前全部跑通：** 在仓库根目录运行 `python -m pytest -q`，全部通过再提交。
- **测试要检查真实行为：** 数值对不对（用手算或解析结果作为预期值）、错误输入会不会报错。
- **预期值不能用被测函数自己算。**
- **测试数据用小的人工数组或图片**，在测试里现场生成。大文件不要提交。
- **人工构造的测试数据要先确认方向对。** 例如正视差要求 `right(x) = left(x + d)`。测试结果明显不对时，先怀疑测试数据，再怀疑算法。

---

## 6. 提交

- **提交前先看一眼 `git status`，** 确认只有自己想提交的文件。
- **改了什么就提交什么。** 不要 `git add .` 一把全提交。
- **流程：** 先 `git pull`，再提交、推送。
- **每个任务在 `docs/任务记录.md` 末尾记一条：** 做了什么、改了哪些文件、结果、怎么复跑、还剩什么，不重要的内容请勿写入该文档。

---

## 7. 汇报结果

说清楚结果是在什么数据上得到的：人工构造、公开数据、仿真、实拍，还是板子。

"在人工图上误差 0.1 像素"和"在烤箱里误差 0.1 像素"是完全不同的结论。
