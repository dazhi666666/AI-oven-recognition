## 1. 一句话

**你负责"统一打分"：定好怎么算分，写好打分程序和运行命令，每个阶段末统一跑一遍出成绩。**

各模块自己接入运行命令、用你的打分程序跑实验；对比表由 B 汇编；板子由 A 负责。

## 2. 你负责什么

- **评测规则：** 误差怎么算、覆盖率怎么算、距离怎么分档、多个场景怎么平均。
- **打分程序：** 距离、视差、厚度、体积误差和覆盖率，能按困难条件和距离档分组。
- **运行命令：** 一条命令加一个 YAML 配置文件，带 dry-run（只检查配置和数据是否齐全），并自动保存运行记录。
- **阶段成绩：** M1–M4 每个阶段末统一跑一遍，出成绩表。

**代码主要写在：**
- `src/oven_stereo/evaluation/`
- `src/oven_stereo/pipeline/`
- `configs/experiments/`
- `docs/protocol/`

工具尽量简单，优先只用 Python 标准库、numpy、PyYAML。

## 3. 当前任务：D-01 评测规则 + 距离打分程序

**为什么做：** 评测规则要在看到成绩之前定好，不然容易"先射箭后画靶"。

**做什么：**

1. **写评测规则草稿**（放在 `docs/protocol/`），回答下面这些问题，写好后拿去和大家讨论：

| 问题 | 建议 |
|---|---|
| 距离误差怎么算 | 相对误差 = \|算出的距离 − 真实距离\| ÷ 真实距离 |
| 在哪些点上算 | 标准答案有效**并且**算法也给出结果的点 |
| 覆盖率怎么算 | 上面这些点的数量 ÷ 标准答案有效的点数 |
| 距离怎么分档 | 0.3–1.0 m、1.0–1.5 m |
| 报哪些数 | 中位数、95 分位 |
| 多个场景怎么平均 | 每个场景单独算，再等权平均；全像素汇总另列 |
| 计时范围 | 从哪一步算到哪一步 |

计算量和内存怎么数由 A 提出，成本和功耗怎么算由 B 提出，你一起收进评测规则。

2. **写距离打分函数**（放在 `src/oven_stereo/evaluation/`）：
   - 写成纯函数，A、C 可以直接调用；
   - 同时输出误差和覆盖率；
   - 没有可打分的点时，误差返回 `null`，不要返回 0。

**用手算例子检验打分程序：**

| 例子 | 标准答案 | 算法结果 | 预期 |
|---|---|---|---|
| 部分有效 | [1, 2, 4] 米 | [1.1, 1.8, 无效] | 误差中位数 10%，覆盖率 2/3 |
| 全部无效 | [1, 2, 4] 米 | 全部无效 | 覆盖率 0，误差 `null`（不是 0%） |

**交付：** 规则草稿、打分函数、测试、给 A 和 C 的调用说明。

## 6. 常见坑

| 坑 | 怎么避免 |
|---|---|
| 没有可打分的点时报 0% 误差 | 应该报 `null`。0% 的意思是"完全准确" |
| 覆盖率用全图像素数做分母 | 分母应该是"标准答案有效的点" |
| `np.median` 遇到 NaN 返回 NaN | 先用掩膜筛掉无效点；筛完是空的，就直接返回 `null` |
| 多个场景的像素直接混在一起算 | 默认每个场景单独算再平均；全像素汇总另列 |
| 读取失败的样本没有计入总数 | 也要计入，并标为失败 |
| 照抄 C 的公式 | 两边会一起错。自己独立写，用手算例子检验 |
