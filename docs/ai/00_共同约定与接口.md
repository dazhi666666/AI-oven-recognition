## 2. 几条底线

只有下面这几条是硬性要求，因为违反了，结果就不可信：

1. **不编造。** 不编造数据、参数和标准答案；缺什么就说缺什么。
2. **算法不看答案。** 算法运行时不读标准答案；检验用的预期值，不用被测程序自己算。
3. **测不出来就标无效。** 测不出的点在数组里填 NaN，再附一张有效掩膜，不填 0。0 是合法的距离和高度，会被当成真实结果参与计算。
4. **失败样本不删。** 难的、失败的样本照样计入结果。

另外，汇报结果时顺带说明是在哪种数据、哪个平台上得到的，比如公开数据、仿真、实拍还是板子。不同来源的数字差别很大。

### 运行和打分怎么配合

- 各模块自己接入运行命令，自己用打分程序跑实验；
- 每个阶段末由 D 统一跑一遍出成绩；
- 对比表由 B 汇编，各模块的说明文档各写各的。

## 5. 模块之间交换的数据

代码放在 `src/oven_stereo/contracts/`，括号里是主要产出这份数据的人。

### 5.1 样本：一组左右图及其参数（B）

输入代码格式见 `contracts.StereoSample`；答案通过独立的 `contracts.ReferenceData` 传递，二者定义在 `contracts/sample.py`。Middlebury 获取与复跑见 [B-01](../data/B-01_公开场景包.md)。

| 字段 | 类型 | 含义 |
|---|---|---|
| `sample_id` | 字符串 | 唯一编号 |
| `left_path`、`right_path` | 路径 | 左图、右图 |
| `image_size_px` | `[宽, 高]` | 图像尺寸 |
| `source`、`source_version` | 字符串 | 来源和版本，如 Middlebury 2014 |
| `domain` | `public` / `synthetic` / `real` | 公开 / 仿真 / 实拍 |
| `split` | 字符串 | 开发集还是测试集 |
| `conditions` | 字典 | 光照、蒸汽、油污、透明/反光、材质、距离档、纹理档；不知道就填 null |
| `rectified` | 布尔 | 左右图是否已"摆正" |
| `calibration_id` | 字符串 | 标定版本 |
| `calibration` | 字典 | 左右相机焦距和主点、间距 `baseline_m`（米）、主点差 `doffs_px`（= 右相机主点 x − 左相机主点 x，Middlebury 约定，距离 Z = f·B/(d + doffs)）、对应分辨率；自有模组另加标定误差、温度、校正映射路径。代码见 `contracts.RectifiedStereo` |
| `metric_depth_available` | 布尔 | 参数是否齐全、能否换算成米 |

**标准答案单独存放**，不放进样本里。答案包（`reference`）包括：真实视差或距离、有效掩膜、单位、来源；实拍样本另附卡尺测量记录。

### 5.2 深度结果（C，代码见 `contracts.DepthResult`）

| 字段 | 类型 | 含义 |
|---|---|---|
| `disparity_px` | `float32[高,宽]` | 视差（像素），以左图为准；视差 = 左图横坐标 − 右图横坐标 |
| `disparity_valid_mask` | `bool[高,宽]` | 哪些点有视差 |
| `confidence` | `float32[高,宽]`，可选 | 可信度，取值 0–1 |
| `depth_m` | `float32[高,宽]` | 距左摄像头的距离（米，沿镜头方向）；参数不齐时不输出，状态写 `disparity_only` |
| `depth_valid_mask` | `bool[高,宽]` | 哪些点有距离 |
| `resolution_profile` | 字符串 | `native` / `320x240` / `160x120` |
| `health.window_contamination` | 字典 | 镜头脏污程度、是否提醒 |
| `sample_id`、`calibration_id`、`method`、`config_id` | 字符串 | 对应哪组图、哪版标定、什么方法、哪个配置 |
| `timings_ms` | 字典 | 各步骤耗时 |
| `status`、`reason` | 字符串 | 成功或失败，以及原因 |

数组用 `.npy` 保存，彩色图只作预览；JSON 里的缺失值写 `null`。

### 5.3 几何结果（A）

- **输入：** 距离图和有效掩膜、相机内参、用于拟合平面的裸露托盘区域、目标区域（`roi_source` 标明是给定的 `reference` 还是自动找的 `auto`）。
- **坐标：** x 向右、y 向下、z 向前，以左摄像头为原点。
- **深度：** `depth_m` 是点沿左相机 z 轴的坐标，不是光心到点的欧氏距离。
- **托盘平面：** `n·X + d = 0`，`n` 为单位法向量，统一朝相机/食物侧，因此 `d>0`；高度 `h=n·X+d`。
- **输出：** `height_m` 高度地图、`thickness_mm` 最大厚度、`volume_ml` 体积、覆盖率、托盘平面、配置版本、`status`、`reason`。

**三种状态：**

| 状态 | 含义 | 体积填什么 |
|---|---|---|
| `ok` | 正常测出 | 数值 |
| `empty` | 托盘上确认没东西 | 0 |
| `rejected` | 有东西但数据不够 | `null` |

**体积计算：** 按托盘上的真实面积累加，不要直接把像素高度相加。远处一个像素对应的面积更大。

**A-02 已实现的子接口：** `geometry.measure_height_grid` 接收已知支撑平面上的二维物理单元高度（m）、单元面积（m²）、独立的目标/有效 bool 掩膜，返回 `contracts.GeometryResult`。它本身不接收距离图或估计托盘平面；完整流程由下方 A-03 接口负责。

- `height_m`、`cell_area_m2` 为 float64；高度无效处为 NaN，`valid_mask=False`。
- `grid_size=[宽,高]`，`grid_representation=support_plane_cells`，不是图像像素或网格节点；`height_reference=support_plane_normal`。
- 本轮 `roi_source=reference`、`tray_plane=null`；不伪造平面参数。
- `coverage=有效目标格数/全部目标格数`；空目标为 null，空目标的厚度与体积为 0。
- 任一目标格不可靠或数值溢出，整件 `rejected`，两个测量标量均为 null；不输出部分体积。
- 保存四个同形状 `.npy`（高度、面积、目标掩膜、有效掩膜）和 `result.json`，详见 [A-02 说明](../geometry/A-02_高度网格测量.md)。

**A-03 已实现的深度接口：** `geometry.measure_depth_geometry` 接收左相机 z 深度、深度有效掩膜、外部给定的目标/托盘 bool 掩膜和 `contracts.PinholeIntrinsics`，拟合 `contracts.TrayPlane`，生成托盘法向高度与支撑平面单元面积，然后复用 A-02 积分。

- 反投影：`X=(u-cx)Z/fx`、`Y=(v-cy)Z/fy`；整数像素坐标代表像素中心。
- 面积：把像素四角射线投到托盘平面，求四边形面积；不是图像像素数，也不是物体表面斜面面积。
- 托盘拟合只使用 `tray_mask & depth_valid_mask`；目标与托盘掩膜不能重叠，少于 3 个或共线的托盘点拒绝拟合。
- 本轮 `roi_source=reference`；平面拟合没有离群点剔除，不等于自动找托盘或真实场景鲁棒性已经完成。
- 完整坐标、接口和人工验收用例见 [A-03 说明](../geometry/A-03_深度到托盘高度.md)。

### 5.6 运行记录与汇总（D 的运行命令自动保存）

**运行记录**包括：配置、代码版本、用到的样本、每个样本的结果状态。

**汇总方式：**
- 多个场景先各自算指标，再等权平均；全像素汇总另列。
