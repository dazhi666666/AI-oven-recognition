## 1. 一句话

**核心算法归你：在左右图里找对应点，把视差估准到零点几个像素，换算成距离，并标出哪里算不准。**

任务书的距离精度和覆盖率主要靠你。难点在于两方面：

- 要在每帧 1200 万次乘加、内存 200 KB 的限制内完成；
- 按推算，160×120 的图上，1 米处视差要估准到约 0.4 像素。

所以亚像素细化是核心工作，C-02 会在第 5 周前验证它能不能做到。

## 2. 你负责什么

- **传统基线**：OpenCV 的 BM/SGBM，以及它在困难条件下的成绩。
- **小图和预算**：160×120 / 320×240 下的匹配、亚像素、逐行处理，以及计算量估算。
- **学习方法**：在预算内做轻量的细化或补洞。电脑上的大模型只用来看上限，或者当"老师"来训练小模型。
- **距离换算**：视差到距离的换算，以及判断哪些点能换算。
- **可信度**：左右互相校验、可信度评分、标出失败的位置。
- **难测场景**：处理无纹理、反光、透明的物体；检测镜头脏污。
- **实验**：自己跑参数对比，自己出"精度 vs 计算量"对比表。
- **板上程序**：按 A 定的接口，写板上的匹配程序。

**代码主要写在：**
- `src/oven_stereo/stereo/`
- `edge/src/match/`
- `configs/stereo/`、`search/`


## 3. 当前任务：C-01 第一张视差图

**为什么做：** 先用最成熟的现成算法（OpenCV SGBM）做出一个能用的版本。后面所有改进都要和它比，才知道有没有进步。这一步只要求算得对，不追求 5% 的精度。

**依赖：** 需要 B-01 的数据。B 那边还没好时，可以先拿人工构造的图测试。

**做什么：**

1. **检查输入**：尺寸一致，左右没有弄反，标定对得上。
2. **算视差**：用写在配置文件里的 SGBM 参数计算视差，并说明视差搜索范围是怎么定的。
3. **处理输出格式**：SGBM 输出的值放大了 16 倍，还要把无效值转成 NaN 和掩膜。详见第 6 节的常见坑。
4. **保存视差**：按原图尺寸保存 `disparity_px` 和掩膜，数值存成 `.npy`。
5. **换算距离**：标定参数齐全时，把视差换算成距离；不齐时，状态写 `disparity_only`。
6. **对答案**：算法函数本身不接收标准答案。想用标准答案检验换算公式，另写一个单独的测试。
7. **写错误用例**：比如尺寸不对、参数非法。

**交付：** 计算函数、配置文件、视差和距离的数值文件、无效点的比例、复跑方法。

## 6. 常见坑

| 坑 | 怎么避免 |
|---|---|
| SGBM 的输出放大了 16 倍 | `compute()` 返回 16 位整数，真实视差 = 输出值 ÷ 16。先用实际输出确认，别重复除 |
| SGBM 的无效值 | 无效点的值等于 `(minDisparity − 1) × 16`，要转成 NaN 和掩膜 |
| `numDisparities` 报错 | 必须是 16 的倍数；`blockSize` 必须是奇数 |
| P1、P2 怎么设 | 常用经验值：P1 = 8 × 通道数 × blockSize²，P2 = 32 × 通道数 × blockSize² |
| 用标准答案的视差范围定搜索范围 | 这等于偷看答案。应该由工作距离和相机参数推出搜索范围 |
| 只交彩色视差图 | 彩色图没法打分，必须交数值文件 |
| 把空洞全部填满 | 填出来的值大多是错的，还会让覆盖率虚高。宁可留空 |
| Middlebury 公式忘了加 `doffs` | 分母是"视差 + doffs"，不是只有视差 |
| 对着测试集调参 | 只在开发集上调参 |
