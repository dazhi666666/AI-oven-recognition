## 1. 一句话

**数据和物料这一头的事都归你：准备别人敢用的数据和标准答案，搭拍摄台架和环境测试台，算清楚成本，最后汇编对比表。**

双目系统的错误，一大半出在数据上：左右图弄反、单位弄错、视差编码读错、坐标方向搞混。所以你交付的不是"一堆图片"，而是**核对过、说得清来龙去脉的数据包**。

仿真也由你负责。原因很简单：出题的人和答题的人分开，标准答案才可信。

## 2. 你负责什么

- **公开数据**：确认来源、版本、许可，读取左右图、标定和标准答案。
- **仿真**：用参数控制腔体、材质、距离、纹理、光照和各种困难条件，批量生成虚拟烤箱数据。
- **台架和实拍**：搭摄像头支架和同步采集程序；实拍时用卡尺测量真值。
- **困难条件**：暗光/偏色、蒸汽、油污、透明/反光四类，分好档，并准备对应数据。
- **划分和质检**：划分开发集和测试集；抽查 ≥10% 的数据。
- **对标和成本**：调研结构光/ToF 的公开参数；核算成本；实测功耗；准备温箱和油污窗；汇编三联对比表和范围取舍文档。

**代码主要写在：**
- `src/oven_stereo/data/`、`synthetic/`
- `configs/data/`
- `data/manifests/`


## 3. 老师的两份材料怎么用

- **《课题二数据集.pdf》**：是"去哪找数据、数据长什么样"的指南。按它的说明，先选**一个**有公开标准答案的 Middlebury 场景。
- **食材 Excel**：后期拍食物、做仿真材质时当参考清单用。表里每样食物的两张照片不是双目图，不要拿来配对算视差。

老师给的格式说明，要和实际下载到的版本对一下。有出入时以实际文件为准，并记录下来。

## 4. 当前任务：B-01 公开测试场景包

**为什么做：** 给 C 一个"标准答案已知"的输入，用来检查程序有没有写错，比如单位、方向、编码。烤箱场景的距离和分辨率问题，后面靠仿真和实拍解决。

**做什么：**

1. **准备文件。** 本地有就直接用；没有就只下载需要的那一个场景（左图、右图、`calib.txt`、标准视差），不用下载整个数据库。
2. **检查左右图。** 确认左右没弄反、尺寸和标定一致、是否已经"摆正"。
3. **读标定。** 间距转成米，焦距和主点差保持像素单位。
4. **读标准视差。** 注意 PFM 格式的细节，见第 7 节常见坑。
5. **分开存放。** 输入包（左右图 + 标定）和答案包（视差 + 有效掩膜）分开存放。
6. **手算核对。** 挑几个像素手算距离，确认读取正确。手算不调用 C 的程序。
7. **错误测试。** 写缺图、尺寸不对等情况的测试。

**距离公式**（Middlebury 2014 已摆正场景专用）：

```
距离 = 间距 × 焦距 ÷ (视差 + doffs)
```

其中 `doffs` = 右相机主点 x − 左相机主点 x（Middlebury `calib.txt` 里的值可直接用，代码里对应 `RectifiedStereo.doffs_px`）。注意：这个公式不能直接套用到其他相机或其他数据集。

**交付：**
- 读取程序（输出符合共同约定 5.1 的格式）
- 文件清单
- 手算核对点
- 错误测试
- 复跑方法

## 7. 常见坑

| 坑 | 怎么避免 |
|---|---|
| Middlebury 的间距单位是**毫米** | 换算成米时除以 1000 |
| PFM 文件上下颠倒 | PFM 从最后一行往上存，读完要翻转；用几个已知位置核对方向 |
| PFM 字节序 | 文件头里的缩放值为负表示小端，为正表示大端 |
| 无效视差 | Middlebury 用 `inf` 表示无效，要转成掩膜，不要当数值参与计算 |
| OpenCV 读图是 BGR 顺序 | 交给别人时说明通道顺序 |
| 左右图弄反 | 近处物体在左图里应该比在右图里更靠右，可以用这一点检查 |
| 看到成绩后换测试样本 | 测试集划定后尽量不改；确实要改时，写明原因 |
| 仿真参数写死在脚本里 | 写进配置文件，保证同样的配置能重新生成相同的数据 |
| 对标参数没有出处 | 每个数字都注明来源，查不到就空着 |
