# C：双目匹配、米制深度与可信区域

## 1. 你的工作究竟是什么

你负责回答：“左右相机都看见的区域如何对应，这个对应有多可靠，能否换算成正确单位的深度？”

你的模块是“左右图 + 已核验标定 + 固定配置 → 数值视差/深度 + 有效区域”。你不测食品体积，不设计整个实验平台，也不从真值生成漂亮的预测图。

当前先用现成传统方法建立能解释、能复跑的基线。做研究不等于首周自写完整SGM或训练大模型。

## 2. 责任分解与边界

| 内容 | 你负责 | 目前不负责 |
|---|---|---|
| 匹配器 | OpenCV SGBM最小封装、参数含义与数值输出 | 从零实现SGM或训练深度网络 |
| 深度转换 | 视差单位、主点差、合法尺度与深度掩膜 | 修改数据集原标定或借用别的相机参数 |
| 可信度 | 先显式无效处理，后续做一致性与失败定位 | 静默补全所有空洞或只留容易像素 |
| 对照实验 | 开发集固定配置、有限因素变化 | 根据每张评测真值挑最优参数 |
| 合成数据 | 后续规则场景的双目渲染与已知参数输出 | 首周写实烤箱/食品场景或完整仿真平台 |

## 3. C-01：第一轮唯一授权任务

### 任务目标

对B提供的一个完整、已校正公开图像对，保存可复现的数值视差；尺度可用时输出轴向深度和有效掩膜。先验证链路正确，不承诺达到5%目标。

### 依赖和不等待事项

- 依赖B提供左右图、标定、原始尺寸与坐标约定。
- 数据包未好时，可实现匹配封装、参数检查和独立换算测试；测试数据明确标为人工构造，不能算真实场景完成。
- 不等相机、开发板、食品或烤箱参数。

### 实施步骤

1. 校验图像可读、尺寸一致、左右顺序、标定ID与分辨率；未知校正状态不得强行作为已校正输入。
2. 用一套明确记录的SGBM配置计算视差，解释视差搜索范围依据；不把数据集GT逐像素范围当作预测辅助输入。
3. 按实际OpenCV输出类型处理定点缩放及无效编码；常见SGBM定点视差需除16，但必须以实际API输出核验，不对已是像素浮点值再次除16。
4. 输出原尺寸`disparity_px`、`disparity_valid_mask`，保留NaN/有效掩膜与数值文件，不只保存彩色图。
5. 对本场景按已核验的参数转换米制轴向深度；明确分母条件与深度有效域。标定缺失则返回`disparity_only`，不编造深度。
6. 将预测函数与参考验证函数分开。可在独立测试中将参考视差用于换算核验，但参考包不得传入预测函数，也不得生成冒充预测的输出。
7. 保存输入ID、参数、版本、方法和计时范围；增加错尺寸、非法搜索参数、非法标定等最小错误用例。

- 同一输入和配置能重复生成数值结果；若有非确定性则记录来源与变化，不用单次截图证明稳定。
- 可独立手算核对若干合法视差的深度换算；B检查参数与尺度，A检查深度/点云方向。
